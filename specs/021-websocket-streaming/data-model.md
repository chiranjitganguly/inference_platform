# Data Model: WebSocket Streaming

**Branch**: `021-websocket-streaming` | **Date**: 2026-06-07

All entities are **runtime-only** (in-memory or on-wire). No new database tables.
The platform's no-persistence constraint (constitution §2.4) applies in full.

---

## 1. WSConnection (runtime, in app.state)

Tracks the lifecycle of one open WebSocket connection. Stored in `app.state.ws_connections` as a simple counter per consumer.

| Field | Type | Notes |
|---|---|---|
| `consumer_id` | `str` | `X-Consumer-Username` header set by Kong key-auth |
| `connection_count` | `int` | Active connections for this consumer; max = `WS_MAX_CONNECTIONS_PER_KEY` |

**State transitions**:
```
CONNECTING → IDLE ↔ STREAMING → CLOSING → (removed)
```

- `CONNECTING`: HTTP upgrade in progress; key-auth validated by Kong before reaching guardrails.
- `IDLE`: Connection open, no stream in progress; accepts new payloads.
- `STREAMING`: Active SSE-to-WS bridge in progress; rejects new payloads with `stream_in_progress`.
- `CLOSING`: Idle timeout or caller disconnect; sends `connection_closing` message, then closes.

---

## 2. StreamRequest (runtime, per WS message)

Represents one chat completion request received over an open WS connection. Lives for the duration of one stream. Not persisted.

| Field | Type | Notes |
|---|---|---|
| `request_id` | `str` | UUID generated by the guardrails handler per message; set as `X-Request-ID` on LiteLLM call |
| `connection_id` | `str` | UUID assigned when the WS connection opens |
| `consumer_id` | `str` | From `X-Consumer-Username` |
| `model` | `str` | Requested model name from the client payload |
| `started_at` | `datetime` | When the handler accepted the request |
| `state` | `str` | `streaming` / `complete` / `error` |
| `otel_span` | span | Open OTel CHAIN span; closed on `complete` or `error` |

## 3. WireMessage — Client → Server

JSON object sent by the caller over the WebSocket. Schema mirrors OpenAI `/v1/chat/completions` request body. The `stream` field is ignored; the handler always forces it to `true`.

```json
{
  "model": "gpt-4o-mini",
  "messages": [
    {"role": "user", "content": "Hello"}
  ],
  "temperature": 0.7
}
```

**Validation rules** (applied by guardrails handler before forwarding):
- `model` must be a non-empty string.
- `messages` must be a non-empty array.
- Additional fields pass through unchanged to LiteLLM.
- Vision gate, function-calling gate, and structured-output gate each run (same logic as the HTTP path) before the SSE call is made.

---

## 4. WireMessage — Server → Client (Token Delta)

Forwarded verbatim from the LiteLLM SSE `data:` line. OpenAI streaming chunk format.

```json
{
  "id": "chatcmpl-abc123",
  "object": "chat.completion.chunk",
  "model": "gpt-4o-mini",
  "choices": [
    {
      "delta": {"content": "Hello"},
      "index": 0,
      "finish_reason": null
    }
  ]
}
```

---

## 5. WireMessage — Server → Client (Stream Complete sentinel)

Sent immediately after the final LiteLLM chunk (the one with `finish_reason` set).

```json
{"type": "stream_complete"}
```

---

## 6. WireMessage — Server → Client (Error)

Sent for any error condition. The connection stays open after all error types except `auth_error` and `connection_closing`.

| `type` | Connection stays open? | Trigger |
|---|---|---|
| `validation_error` | Yes | Malformed payload, gate rejection |
| `stream_in_progress` | Yes | Second payload during active stream |
| `rate_limit_error` | Yes | LiteLLM 429 response |
| `model_error` | Yes | LiteLLM non-200 response mid-stream |
| `stream_error` | Yes | Any mid-stream upstream error |
| `auth_error` | No (closes) | Credential expired post-connect |
| `connection_limit_exceeded` | No (rejected at handshake) | >10 connections for this API key |
| `connection_closing` | No (closes) | Idle timeout |

```json
{
  "type": "stream_in_progress",
  "error": "stream_in_progress",
  "message": "A stream is already active. Wait for stream_complete before sending a new request.",
  "detail": {}
}
```

## 7. Audit Log Entry (written to Loki per stream request)

Same structure as the existing HTTP audit log. No new fields. No prompt content.

| Field | Value |
|---|---|
| `timestamp` | ISO-8601 UTC |
| `event_type` | `"ws_stream_request"` |
| `request_id` | UUID from `StreamRequest.request_id` |
| `key_hash` | SHA-256 of consumer API key (not the key itself) |
| `model` | Requested model name |
| `pii_entity_count` | Count of PII entities redacted by Presidio |
| `scanner_blocked` | `true` / `false` |
| `stream_error` | `true` / `false` |

## 8. Environment Variables (new, guardrails service)

| Variable | Default | Notes |
|---|---|---|
| `WS_MAX_CONNECTIONS_PER_KEY` | `10` | Per-consumer connection limit; configurable without code change |
| `WS_IDLE_TIMEOUT_SECONDS` | `300` | Connection idle timeout; configurable without code change |
