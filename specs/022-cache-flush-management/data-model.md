# Data Model: Cache Flush Management

**Feature**: 022-cache-flush-management
**Date**: 2026-06-08

---

## Entities

### CacheFlushRequest

Represents a single flush operation request received by the endpoint.

| Field | Type | Required | Constraints |
|---|---|---|---|
| `request_id` | UUID string | Yes | Auto-generated by Kong (`X-Request-ID`) |
| `scope` | enum: `all` \| `model` | Yes | Derived from presence of `?model=` parameter |
| `model` | string \| null | No | Present only when `scope = model`; validated against model catalogue |
| `key_hash` | string | Yes | SHA-256 of the raw `Authorization` header value; never the raw key |
| `received_at` | ISO-8601 UTC timestamp | Yes | Recorded at request entry |

**Validation rules**:
- `model` MUST match a name in the live LiteLLM model catalogue (returned by `GET /v1/models`)
- `model` MUST contain only alphanumeric characters, hyphens, underscores, and dots; max 128 characters
- If `model` is present but empty string: treated as validation error (HTTP 422)

---

### CacheFlushResult

Represents the outcome of a completed flush operation.

| Field | Type | Notes |
|---|---|---|
| `keys_deleted` | integer ≥ 0 | Count of Redis keys removed |
| `scope` | enum: `all` \| `model` | Mirrors the request scope |
| `model` | string \| null | Mirrors the request model; null for full flush |
| `duration_ms` | integer | Wall-clock milliseconds for the SCAN+DEL operation |

**Wire format** (HTTP 200 response body):

Full flush:
```json
{
  "keys_deleted": 142
}
```

Model-scoped flush:
```json
{
  "keys_deleted": 37,
  "model": "gpt-4o"
}
```

---

### CacheAuditEntry

Written to Loki after every flush attempt (success or failure). Contains no cache key names and no raw credentials — metadata only (constitution §II).

| Field | Type | Value |
|---|---|---|
| `timestamp` | ISO-8601 UTC | Time of flush completion |
| `event_type` | string | `cache_flush_all` or `cache_flush_model` |
| `request_id` | UUID string | From `X-Request-ID` header |
| `key_hash` | string | SHA-256 of the raw master key |
| `model` | string | Model name or literal `"all"` |
| `keys_deleted` | integer | 0 if auth failed or cache was empty |
| `status_code` | integer | HTTP status returned to caller |

---

## Redis Key Namespace

Cache entries written by LiteLLM follow this key pattern:

```
llm_cache:<model-name>:<request-fingerprint-hash>
```

| Flush scope | SCAN pattern |
|---|---|
| Full flush | `llm_cache:*` |
| Model-scoped flush | `llm_cache:<model-name>:*` |

**Important**: The SCAN pattern targets only `llm_cache:*` keys. No other Redis keys (rate-limit counters, session tokens, queue entries on port 6380) are touched.

---

## Error Response Shape

All error responses use the platform-standard structured error format (constitution §III):

```json
{
  "error": "<machine_readable_code>",
  "message": "<human readable description>",
  "detail": {}
}
```

| HTTP Status | `error` value | Condition |
|---|---|---|
| 401 | `unauthorized` | No `Authorization` header |
| 403 | `forbidden` | Valid key but not the master key |
| 422 | `invalid_model` | `?model=` value not in catalogue; `detail` includes `valid_models` list |
| 503 | `cache_unavailable` | Redis unreachable |
| 503 | `model_catalogue_unavailable` | LiteLLM unreachable during model name validation |
