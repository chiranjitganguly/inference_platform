# Implementation Plan: Gateway API Versioning

**Branch**: `016-gateway-api-versioning` | **Date**: 2026-06-03 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/016-gateway-api-versioning/spec.md`

---

## Summary

Add stable v1 and new v2 routing tiers to the Kong gateway. Both tiers upstream to the same LiteLLM instance (`http://litellm:4000/v1`). Every response receives an `X-API-Version` header reflecting the version that served it (`1` for v1 routes, `2` for v2 routes). Deprecated endpoints signal their removal date via `Deprecation`, `Sunset`, and `Link` headers added as route-level response-transformer plugins. The implementation is a single-file Kong declarative config change (`services/kong/kong.yml`) plus smoke test additions.

## Design: Kong Config Changes

### Change 1 — Global `response-transformer`: remove `X-API-Version`

The global plugin retains only `X-Platform`. `X-API-Version` moves to service scope.

```yaml
# BEFORE
- name: response-transformer
  config:
    add:
      headers:
        - "X-Platform: inference-platform"
        - "X-API-Version: 1"

# AFTER
- name: response-transformer
  config:
    add:
      headers:
        - "X-Platform: inference-platform"
```

**Why**: Kong `response-transformer` `add` action is a no-op if the header already exists. Route/service-scope plugins run before global plugins in `header_filter` phase. A service-scoped `add X-API-Version: 2` on the v2 service runs before the global `add X-API-Version: 1` — making the global plugin a no-op for v2. Moving to service scope gives each service an independent value with no ordering conflict.

---

### Change 2 — `litellm`, `litellm-embeddings`, `litellm-admin` services: add service-level plugin

```yaml
# Added to each of these three services:
plugins:
  - name: response-transformer
    config:
      add:
        headers:
          - "X-API-Version: 1"
```

No route changes. Timeout and auth config unchanged.

---

### Change 3 — New `litellm-v2` service

```yaml
- name: litellm-v2
  url: http://litellm:4000/v1       # /v2/chat/completions → strip /v2 → /chat/completions → appended to base → /v1/chat/completions ✓
  connect_timeout: 10000
  read_timeout:    60000
  write_timeout:   60000
  plugins:
    - name: response-transformer
      config:
        add:
          headers:
            - "X-API-Version: 2"
  routes:
    - name: v2-proxy
      paths:
        - /v2
      methods:
        - GET
        - POST
      strip_path: true
      plugins:
        - name: key-auth
          config:
            key_names:
              - Authorization
            key_in_header: true
            hide_credentials: true
```

**Path rewrite logic**: `strip_path: true` strips the matched route prefix (`/v2`). The remainder (e.g., `/chat/completions`) is appended to the service URL (`http://litellm:4000/v1`). Result: LiteLLM receives `POST http://litellm:4000/v1/chat/completions` — its native OpenAI-compatible path. Model names resolve identically for v1 and v2.

---

### Change 4 — Deprecation pattern (documented, not applied to any live route yet)

When an operator needs to deprecate a route, they add a route-level plugin:

```yaml
- name: response-transformer
  config:
    add:
      headers:
        - "Deprecation: {HTTP-date of announcement}"
        - "Sunset: {HTTP-date of removal, ≥6 months after Deprecation}"
        - 'Link: <{/path/to/migration/docs}>; rel="deprecation"'
```

Post-sunset behaviour: Remove the route entirely from `kong.yml` and add a dedicated route returning HTTP 410 with a `Link` header.

## Acceptance Criteria

All criteria are `curl`-verifiable against `http://localhost:8080`.

| ID | Test | Command | Expected |
|----|------|---------|----------|
| AC-001 | v1 models header | `curl -si -H "Authorization: Bearer $SMOKE_API_KEY" http://localhost:8080/v1/models` | `X-API-Version: 1` in response |
| AC-002 | v1 chat header | `curl -si -H "Authorization: Bearer $SMOKE_API_KEY" -d '{"model":"gpt-4o-mini","messages":[...]}' http://localhost:8080/v1/chat/completions` | `X-API-Version: 1` in response |
| AC-003 | v2 models header | `curl -si -H "Authorization: Bearer $SMOKE_API_KEY" http://localhost:8080/v2/models` | `X-API-Version: 2` in response, HTTP 200 |
| AC-004 | v2 chat header | `curl -si -H "Authorization: Bearer $SMOKE_API_KEY" -d '{"model":"gpt-4o-mini","messages":[...]}' http://localhost:8080/v2/chat/completions` | `X-API-Version: 2` in response, HTTP 200 |
| AC-005 | Model alias stability | Same command as AC-004 with `model: gpt-4o-mini` | HTTP 200 (model resolved, not 404) |
| AC-006 | Unknown version | `curl -si http://localhost:8080/v3/models` | HTTP 404; `X-API-Version` header absent |
| AC-007 | X-Platform retained | Any of AC-001–AC-004 response | `X-Platform: inference-platform` present |
| AC-008 | X-Request-ID retained | Any of AC-001–AC-004 response | `X-Request-ID: {uuid}` present |
| AC-009 | Deprecation headers | `curl -si -H "Authorization: Bearer $SMOKE_API_KEY" http://localhost:8080/v1/{deprecated-route}` | `Deprecation`, `Sunset`, `Link` all present |
| AC-010 | Non-deprecated no deprecation headers | AC-001 or AC-003 response | `Deprecation` and `Sunset` absent |

## Implementation Notes

1. **Spec header value correction**: The spec uses `v1`/`v2`; this plan uses `1`/`2` (matching constitution §4.3 and existing config). The spec should be updated to reflect integer values before closing this feature.

2. **`litellm-health` service**: Health route (`/health`) is version-agnostic and intentionally omits `X-API-Version`. No change needed.

3. **`portal-backend` service** (`/v1/spend`): This service proxies to `portal-backend:8092`, not LiteLLM. It currently has no service-level `response-transformer`. Add `X-API-Version: 1` at service scope for consistency (it lives under the `/v1/` namespace).

4. **Embeddings timeout preserved**: `litellm-embeddings` service retains its 120 s `read_timeout`. The service-level plugin addition does not touch timeouts.

5. **Smoke test additions**: `scripts/smoke-test.sh` must be updated to assert v2 routes return `X-API-Version: 2` and that unknown prefixes return 404 without the version header.
